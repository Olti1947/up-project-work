# Camera-based book cataloguing mobile application with a web collection viewer

## My interpretation of the brief
The project is a mobile / web application which simplifies the process of keeping track of available books by using their phone camera to scan the ISBN barcode and getting the information about the book from a trusted source, in case it is not availabe manual input should still be allowed, and in case a picture can be taken an vision capable AI model can extract the information needed too, before storing the information is always allowed to be double-checked and modified by the user.
Most important aspect of this should be speed and convinience, application should be easy to use and straight-forward, not many flows should be introduced.

## Why I am a good fit for this project
I am interested in Mobile Application Developement and making every day life tasks easier by introducing a software layer which handles mundane tasks for us. I like the concept of including AI into these tasks as long as they don't overcomplicate solutions unneccessarily.

## Relevant experience and background
I have done an internship at a company in Pécs (RabIT Solutions) where I've had the chance to work with developing a fintech mobile app. Besides that I have built a fully functioning mobile / web app for a sushi restaurant (available on my Github) which includes a feature of generating and scanning discount QR codes, these skills could easily be transfered to this problem.

## Proposed approach
I would first like to define the main flow of the application, which is the process from when the user picks up a book to where it gets stored. What's the experience we are aiming for? I would say a fast interaction where a book can get saved in less than 5 seconds. No account needed, no extra step, no additional flows, books can be saved and other stuff can be done later optionally. What is the role of the AI vision capable model? When thinking of a vision capable model we must define what we mean, and the cost it comes with, will we just parse the data? We must aim for fastest possible solution while maintaining quality and optimised cost. User count shouldn't pose a big problem for this app.
